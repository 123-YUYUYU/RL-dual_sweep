# 实验与复现

## 数据隔离

一个主种子分为四个独立随机流：监督样本、RL 训练、网络初始化、测试轨迹。监督样本来自随机策略访问的独立场景，对同一个环境快照枚举所有候选动作，得到一步收益标签；原环境状态保持不变。这里的标签不是长期最优解，不使用测试轨迹。

RL 的每轮环境种子预先生成，以减少策略探索随机数改变训练场景的影响。测试从专属随机流生成；每个策略重置到相同种子，因而共享任务到达、信道和后台负载。预生成轨迹不会作为未来信息输入策略，环境推进也不消耗策略的随机流。

## 训练与加载

DQN 使用经验回放、目标网络、Double-DQN 动作选择与 Huber loss。监督模块用多输出岭回归预测动作的一步奖励，只在探索阶段提供部分动作建议。贪心评估时 RL 直接使用网络输出；`supervised` 基线则单独使用监督模型。

`policy.npz` 和 `guide.npz` 是不含 pickle 的推理模型；不保存优化器状态或经验回放，因此**不支持从这些文件精确恢复训练**。评估从 `config.json` 加载与训练一致的环境维度；更改节点数或状态结构后需要重新训练。更改负载分布也应作为单独实验保存。

```bash
python train.py --config configs/default.json --seed 7 --episodes 60 --output outputs/guided
python evaluate.py --run outputs/guided --episodes 5
python train.py --config configs/default.json --seed 7 --episodes 60 --no-supervision --output outputs/rl_only
python evaluate.py --run outputs/rl_only --episodes 5
```

无监督辅助对照仍生成并保存监督模型，用于一致的 `supervised` 评估基线，但训练时不会调用它提供建议。

## 基线含义

| 策略 | 选择规则 |
| --- | --- |
| `local_first` | 激活全部边缘候选；兼容时优先本地，必要时卸载 |
| `balanced` | 激活全部边缘；综合当前工作量与传输时间选择位置 |
| `edge_first` | 激活全部边缘；对边缘执行给予偏好 |
| `supervised` | 用独立拟合的监督模型选择高层动作 |
| `rl` | 训练后网络的贪心动作，是否使用监督训练见 run.json |

所有基线和 RL 使用同一内层迭代预算。激活预算、队列和资源使用会随策略而变化；固定全边缘激活的基线会产生相应的空闲能耗。

## 比较口径

至少同时比较任务完成率、超时率、期末剩余任务、时延、总能耗与队列长度。低能耗可能来自较少服务任务，低完成时延可能来自只完成简单任务；需要连同完成率判断。时域结束不会强制清空队列，延长 horizon 可以减小边界任务在指标中的比例。

`summary.csv` 是逐 episode 指标的非加权均值和总体标准差（ddof=0）。时延聚合排除没有完成任务的 episode，所以它不等于把全部任务合并后的平均时延；逐任务重新统计可使用 `tasks.csv`。更严谨的算法性能比较应使用多个独立训练种子，单个网络的多个测试轨迹不能替代多次训练。

结果目录包含实际配置、主种子、训练场景种子、测试种子、NumPy 版本及逐时隙日志。相同环境与依赖下应能复查输出；跨平台浮点线性代数和版本差异可能造成训练轨迹变化，不承诺逐字节一致。

## 测试

```bash
python -m unittest discover -s tests -v
```

检查内容包括任务守恒、队列容量、CPU 与功率预算、模型兼容、跨时隙上传与计算、截止时间、时域终止、外生轨迹配对、快照隔离、终止转移不自举、监督辅助调用、网络更新与模型加载。GitHub Actions 提供 Linux / Python 3.9、3.12 的测试和小规模完整流程；本地是否已验证这些平台应以实际 CI 结果为准。
