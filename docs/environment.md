# 环境与资源模型

## 时隙生命周期

`EdgeSchedulingEnv.reset(seed)` 创建整条外生轨迹并放入首时隙到达任务。`step(action)` 依次执行：

1. 解码边缘节点激活预算、执行位置偏好与模型偏好。
2. 保留已有任务的目的节点，为等待任务按截止时间顺序选择兼容位置。
3. 按当前后台负载计算可用算力，内层优化器分配 CPU 和上传功率。
4. 上传任务推进上传进度；进入本时隙前已上传完毕的任务推进计算进度。
5. 记录完成任务，并丢弃在时隙末到达截止时间的剩余任务。
6. 推进时间并放入下一时隙任务。有限时域结束后返回 `terminated=True`。

任务在上传完成后的**下一个时隙**才能开始计算。已分配任务保持执行位置、模型和剩余工作量，不会因下一步外层动作改变而迁移或重复上传。只在未分配任务上执行调度。

## 单位与异构性

| 量 | 单位 / 约定 |
| --- | --- |
| `slot_seconds` | 秒 / 时隙 |
| `input_mbit` | 任务输入量，Mbit |
| `work_gcycles` | 轻量模型的计算量，Gcycle |
| `device_ghz`, `edge_ghz` | Gcycle/s；计算量除以频率得到秒 |
| `device_power_w` | 每台设备上传任务共享的发射功率上限，W |
| `bandwidth_mhz` | 每台设备的正交信道带宽，MHz，其上传任务均分 |
| `channel` | 已归一化噪声的信道系数，1/W |
| `energy_j` | 发射功率与执行功率按实际使用时长积分，J |

设备仅支持模型 rank 0；边缘节点的最高模型 rank 由 `edge_model_rank` 指定。默认模型规模参考 [Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B) 和 [Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B)，分别配置为 `model_parameters_b: [0.6, 1.7]`。计算需求以轻量模型为基准，按名义参数规模之比换算；该换算是调度负载近似，不是 Qwen3 的实测时延、FLOPs 或能耗比例。节点算力、能耗系数与通信参数独立设置。

每个任务的 `required_rank` 是最低模型等级要求；不支持的任务保持等待，直至可以调度或过期。模型等级是兼容性约束，不表示对真实模型质量的测量。

每个时隙的边缘可用算力为名义算力乘以 `(1 - background_load)`。信道与后台负载沿时间相关变化。泊松任务到达率叠加周期项，构造负载波动。

## 外层动作与状态

`action = edge_budget * 6 + preference * 2 + model_rank`。

- `edge_budget`：0 到边缘节点数。
- `preference`：0 设备优先，1 平衡，2 边缘优先。
- `model_rank`：0 或 1；最终任务模型取偏好与最低需求的较大者。

高层动作交给确定性的截止时间优先分配器，选择具体任务位置。状态由时间、队列量、平均剩余时限、上传/计算剩余工作量、信道、任务等级、节点积压、后台负载及设备等待量构成。网络输入不直接暴露未来轨迹。

已有任务占用的边缘节点必须继续保持激活；外层预算不能中断这些任务。因此 `requested_edges` 是新决策的目标，`active_edges` 可能因已有任务而更大。空闲但被选中激活的节点也计空闲能耗。

## 内层迭代法

`allocate(tasks, config, capacity, channel)` 在固定位置后分别处理正在计算和正在上传的任务。

CPU 代理目标包括剩余工作量除以频率的时间项，以及频率平方正则项。上传速率采用带宽乘以 `log2(1 + gain * power)`；上传代理目标包括剩余输入除以速率的时间项与功率平方正则项。两个子问题均采用投影梯度和回溯下降，资源投影满足节点 CPU 与设备总功率预算。

内层代理目标不等于完整 episode 奖励，也不等于实际能耗表达式；它是公开参考分配器。实际计算能耗按频率立方与使用时间计算，上传能耗按发射功率与上传时间计算，另计激活边缘的空闲能耗。这里不优化带宽，也不模拟设备间干扰。

停止条件采用单位步长投影梯度残差，避免因回溯步长过小而误报收敛。达到预算上限仍会返回可行分配，并如实报告 `inner_converged=0`。`inner_iterations` 为两个并列子问题实际迭代次数的最大值。

## 指标与守恒

一个结束的 episode 满足：

```text
arrived = completed + missed + overflow + pending
```

任务在截止时隙内完成算成功；未完成且达到截止时间记 `missed`；队列满时新到达任务记 `overflow`；时域结束时未到截止时间的任务记 `pending`。没有完成任务时，均值与 P95 时延留空。

奖励为完成任务奖励，减去超时/溢出惩罚、能耗项和积压项；最后一个时隙额外惩罚剩余任务。它是一组通用参考权重，可通过替换环境奖励逻辑进行实验。

`trace.csv` 中的 `queue` 对应 step 返回的下一决策状态，包含下一时隙新到达任务；其余服务指标对应刚处理完的 `slot`。期初队列溢出在首次 step 计入奖励；之后的溢出在相应任务到达后的服务 step 计入。期末不再引入新到达。
